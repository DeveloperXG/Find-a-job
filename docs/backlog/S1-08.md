## Goal
Idempotent fetch → normalize → upsert → closure → dedupe → health, runnable from the CLI.

## Files
- `apps/api/app/ingestion/service.py`
- `apps/api/app/cli.py (ingest command)`
- `apps/api/app/api/jobs.py (minimal `GET /jobs` list for the sprint demo)`
- `apps/api/tests/ingestion/test_service.py`

## Spec
`ingest_source(source_id) -> IngestStats{fetched, new, updated, unchanged, closed, failed}`:
1. Fetch through the adapter.
2. Normalize.
3. Upsert on `(source_id, external_id)`: new → insert with `first_seen_at`; existing with a changed `content_hash` → update and reset `filter_status=pending`; unchanged → touch `last_seen_at` only.
4. **Closure detection:** an open job for this source that's missing from the fetch for **2 consecutive successful polls** gets `status=closed, closed_at=now` (one miss could be a flaky response).
5. **Cross-source dedupe:** if another *open* job has the same `fingerprint`, keep both rows but mark the newer one `raw._duplicate_of=<id>` and exclude it from the feed.
6. Update source health: success resets `consecutive_failures`; failure increments it and stores `last_error`; at 3 failures, `enabled=false` plus an in-app notification.
7. Write a `workflow_runs` row.
CLI: `jt ingest [--source ats:token] [--all]`.

## Acceptance criteria
- running twice yields 0 new on the second run (idempotent).
- the fixture closure scenario passes.
- one failing source doesn't abort `--all`.
- Definition of Done in AGENTS.md §4.

## Test plan
DB tests with a FakeSource returning scripted fetches across polls (new → changed → missing ×2 → closed); failing source among several.

## Out of scope
Filtering (S1-10), scoring, Inngest wiring (S2-07).
