## Goal
The master resume as structured data, rendered to an ATS-friendly PDF on demand.

## Files
- `apps/api/app/resumes/{schema,render,importer}.py`
- `apps/api/app/resumes/templates/resume.typ`
- `apps/api/app/api/resumes.py`
- `apps/api/tests/resumes/**`

## Spec
`ResumeDoc` = `basics{name, email, phone, location, links[]}`, `summary`, `skills[{category, items[]}]`, `experience[{id, company, title, location, start, end, bullets[{id, text, tags[]}]}]`, `projects[{id, name, link, bullets[...]}]`, `education[...]`, `certifications[]`. IDs are stable slugs (`exp-acme`, `exp-acme-b3`). Import: `POST /resumes/master/import` (multipart PDF/DOCX or JSON) → extract text (pypdf / python-docx) → **one** Haiku `EXTRACT` call into ResumeDoc → returned as a *draft* that the user reviews and saves (never auto-saved). `render.py`: Jinja2 → `templates/resume.typ` (single column, standard headings "Experience/Education/Skills", no tables or icons, ASCII bullets) → `typst.compile` → PDF bytes. `GET /resumes/{id}/pdf` renders on demand and **doesn't store PDFs**. Editing the master increments `master_version`.

## Acceptance criteria
- the rendered PDF's text extracted back with pypdf contains every bullet in order (an ATS-parseability proxy).
- Definition of Done in AGENTS.md §4.

## Test plan
Render a fixture ResumeDoc → pypdf text contains every bullet in order; import uses FakeProvider.

## Out of scope
Tailoring (S2-06), DOCX export (Phase 4).
