# S2-06 — Tailoring + anti-fabrication validator + variant reuse

| Points | Model | Depends on | Sprint |
|---|---|---|---|
| 5 | Sonnet | S2-05, S2-02b | 2 — Intelligence & tracking |

## Goal
Job-specific resumes that never invent facts and are reused when possible.

## Files
- `apps/api/app/resumes/{tailor,validate,reuse}.py`
- `apps/api/app/api/jobs.py (tailor route)`
- `apps/api/tests/resumes/test_validate.py`
- `apps/api/tests/resumes/test_tailor.py`

## Spec
`POST /jobs/{id}/tailor`:
1. **Reuse check:** among non-archived variants with the same `role_family` and the current `master_version`, compute the Jaccard similarity of `keyword_signature` against the job's `required_skills`. If it's ≥ 0.75, return `{reused: true, resume_id}`, unless `?force=true`.
2. Otherwise call Sonnet (`TAILOR`) with the master ResumeDoc plus the job text, which returns `TailorPlan{summary, skills_order[], experience[{id, bullets[{source_id, text}]}], projects[...] }`. The model may **select, reorder and reword** but not invent.
3. **Validator** (`resumes/validate.py`, deterministic): every `source_id` exists in the master; every number or percent in the rewritten text appears in its source bullet; every skill in the output exists in the master's skills; at most 2 pages after render (re-render, and if it's over 2 pages, drop the lowest-ranked bullets).
4. On a violation, do one repair call that includes the violation list; if it still fails, return a 422 with the violations (never save a fabricated resume).
5. Save the variant with its `keyword_signature`.
Storage is JSON only, about 10 KB per variant, so even 10k variants is around 100 MB. That answers the "takes up space" concern.

## Acceptance criteria
- validator unit tests with planted fabrications (a new number, a new employer, a new skill) all get rejected.
- Definition of Done in AGENTS.md §4.

## Test plan
Planted fabrications (new number, employer, skill, unknown source_id) rejected; reuse threshold boundary at 0.75.

## Out of scope
Cover letters.
