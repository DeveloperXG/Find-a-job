## Goal
Track applications through the pipeline with auditable events and rule-driven notifications.

## Spec
`POST /applications {job_id, resume_id?}` → status queued (409 if one already exists). The **company cooldown** check warns when another application to the same company falls within `company_cooldown_days`, and `force=true` overrides it. `PATCH /applications/{id}/status {to, stage?, reason?, override?}` → `state_machine.transition` → persists the event → `notify_rules` → dispatches to notifiers. `GET /applications?status=` (board), `GET /applications/{id}/events`. `GET /notifications`, `POST /notifications/{id}/read`. `NtfyNotifier`: POST to `{NTFY_URL}/{NTFY_TOPIC}` with the `Title`, `Priority` and `Click` (deep link) headers. **The topic is a long random string from `.env`, because anyone who knows the topic can read it**; an optional `NTFY_TOKEN` is supported. Notifications dedupe on `dedupe_key = f"{app_id}:{to_status}:{stage}"`.
