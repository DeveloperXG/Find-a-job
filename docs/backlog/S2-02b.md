# S2-02b — Scoring pipeline (prescore → Haiku → cache)

| Points | Model | Depends on | Sprint |
|---|---|---|---|
| 3 | Sonnet | S2-02a | 2 — Intelligence & tracking |

## Goal
Score only what matters, once, within budget.

## Files
- `apps/api/app/matching/{prescore,scorer}.py`
- `apps/api/app/cli.py (score command)`
- `apps/api/tests/matching/test_scorer.py`

## Spec
For jobs with `filter_status=passed` and no `job_matches` row for the current cache key:
1. **Prescore** (free, deterministic): weighted keyword overlap between job text and `profile.candidate.skills` + target title terms (TF-IDF-ish with a stopword list), giving 0–1.
2. Take the top `SCORE_TOP_K` per run (default 60) by prescore, plus every job at a `priority=high` company.
3. Call Haiku with `cached_context = profile JSON + rubric`, max_tokens 600, concurrency 5.
4. Store the match.
5. On `BudgetExceeded`, stop cleanly and leave the remaining jobs `pending` for the next run; the run status becomes `partial`.
Truncate the description to about 3,000 tokens (first 9k chars plus the "requirements/qualifications" section if it was cut off).

## Acceptance criteria
- a second run on unchanged data makes 0 LLM calls (cache hit).
- an injection case doesn't produce a score > 50.
- Definition of Done in AGENTS.md §4.

## Test plan
FakeProvider: cache hit = 0 calls; top-K selection; high-priority company inclusion; BudgetExceeded → partial run.

## Out of scope
Inngest wiring (S2-07).
