# S2-07 — Inngest workflows: discovery cron, poll fan-out, scoring batch

| Points | Model | Depends on | Sprint |

## Goal
Hands-off discovery and scoring every 6 hours, safe to rerun.

## Files
- `apps/api/app/workflows/{discovery,scoring}.py`
- `apps/api/app/worker.py`
- `apps/api/tests/workflows/**`

## Spec
(`workflows/`, registered in `worker.py`):
- `discovery_cron`: cron `0 */6 * * *` → reads the enabled sources → `step.send_event` with `source/poll.requested` per source, using event id `f"{source_id}:{window}"` (window = UTC 6-hour bucket) for idempotency.
- `poll_source`: triggered by `source/poll.requested`; concurrency limit 4 keyed by `event.data.ats`; retries 3; calls `ingest_source`, then `jobs/filter.requested`.
- `filter_and_score`: debounced 2 minutes (so a cron burst collapses into one run); runs the filters, then `score_pending()`.
Each step is a named `step.run` so retries resume mid-flow.

## Acceptance criteria
- with the Inngest dev server, one manual trigger produces a full cycle visible in the dev UI and in `workflow_runs`.
- Definition of Done in AGENTS.md §4.

## Test plan
Unit-test step functions directly; manual end-to-end run in the Inngest dev UI (screenshot in the PR).
